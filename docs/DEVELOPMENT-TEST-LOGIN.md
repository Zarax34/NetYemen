# تسجيل دخول تجريبي للتطوير

## لماذا لا يوجد تجاوز داخل التطبيق؟

كل دوال `SupabaseService` تأخذ `userId` وتستعلم عبر RLS. أي تجاوز محلي لشاشة
OTP سينشئ "تسجيل دخول" بلا جلسة Supabase حقيقية، فتنجح شاشة الدخول ثم تفشل
كل شاشة بعدها (الرصيد، الشبكات، المشتريات). لذلك الحل الصحيح هو **Test OTP**
المدمجة في Supabase: تعطي **جلسة حقيقية** بدون إرسال SMS.

## 1) ضبط الرمز في Supabase (مرة واحدة)

من لوحة Supabase للمشروع:

**Authentication → Sign In / Providers → Phone**

1. فعّل **Enable Phone provider**.
2. افتح **Test OTP** وأضف سطراً بالصيغة:

   ```
   +967771234567=123456
   ```

   الرقم بصيغة E.164 الكاملة، ثم `=`، ثم الرمز المكوّن من 6 أرقام.

   > ⚠️ **لا تستخدم القيم أعلاه كما هي.** هذا الملف منشور في مستودع عام،
   > فأي قيم مكتوبة فيه معروفة للجميع. اختر رقماً غير مستخدم ورمزاً عشوائياً،
   > واحتفظ بهما خارج المستودع.
3. اضبط **Valid until** لتاريخ قريب حتى ينتهي الرمز تلقائياً.
4. احفظ.

بعدها يُرجع `signInWithOtp` نجاحاً بلا SMS، ويُرجع `verifyOTP` بهذا الرمز
جلسة حقيقية.

## 2) التشغيل مع الرقم التجريبي

```bash
flutter run \
  --dart-define=DEV_TEST_PHONE=771234567 \
  --dart-define=DEV_TEST_OTP=123456
```

`DEV_TEST_PHONE` بدون مقدمة الدولة (9 أرقام) — التطبيق يضيف `+967` تلقائياً.

عندها يُعبَّأ الرقم والرمز تلقائياً وتظهر لافتة برتقالية "وضع التطوير"،
فتصل إلى الشاشة الرئيسية بضغطتين.

بدون تمرير الـ defines يعمل التطبيق بالتدفق العادي تماماً.

## حواجز الأمان

- **لا قيم في المستودع.** الرقم والرمز يُمرَّران وقت البناء فقط. المستودع
  عام، وأي رقم/رمز مكتوب في الكود يصبح باباً خلفياً لأي شخص على الإنترنت.
- **مقفل في release.** `DevConfig` محروس بـ `kReleaseMode`، فحتى لو مرّر
  أحدهم الـ defines إلى بناء release تبقى القيم فارغة و`isEnabled` تساوي
  `false`. يغطي ذلك اختبار في `test/utils/dev_config_test.dart`.
- **مؤقت.** احذف الرقم من Test OTP في Supabase قبل الإطلاق، وإلا بقي مدخلاً
  صالحاً للدخول إلى المشروع الحيّ.
